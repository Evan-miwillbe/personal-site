No. 01

Multi-Agent Research
多 Agent 深度研究框架

2026.04 — 2026.05 13 天 · v1 → v9.0 个人独立研究

针对 Claude Code 官方深度研究"机制黑盒、流程不可控"的痛点， 独立设计可自定义虚拟研究团队 Skill。 从 v1.0 到 v9.0 经历 77 次 commit，从 PM 中心制 7-Agent 简化为扁平星型 2-3 Agent，v6.0 较 v5.4 行数下降约 80%（893→221）。

Lost in Middle 效应——关键约束放 prompt 中间合规率 0% (0/6)， 放首尾合规率 100% (6/6)。47 轮实验中通过消融严格区分 "机制有效" 与 "机制必要"，17 个操作钩子中确认 2 个 KEEP、14 个被模型行为内化。

方法论已落地为 knowledge-healer 飞书知识库自愈工具， 入选飞书 CLI 创作者大赛十佳—— 从理论框架到工程产出到第三方认证的完整闭环。

No. 02

knowledge-healer · 飞书知识库自愈巡检

★ 飞书十佳
2026.04 — 2026.05 多 Agent 落地工具 MIT License

新人入职第一天，主管说"去看 wiki 上的报销流程"。 照着走一遍被财务打回。主管说"哦那个早改了，直接提交就行"。 调研显示 70% 以上企业知识库"几乎无人用或仅勉强有人用"—— 写一篇文档是一次性成本，维护是持续成本，没人愿意管。

Knowledge Healer 用 3+2 多 Agent 并行架构对知识库做 7 维健康诊断—— 不只找"文档有没有问题"，还找"该有但没有的内容"。 关键创新：跨源交叉验证（文档 vs 群聊），检测知识漂移—— 文档没改，但群里有人说"我们现在不这么做了"， 这是纯文档检查工具做不到的。

No. 03

lark-survey-scoreboard · 飞书实时评分大屏

★ 飞书十佳
2026.04 来源 · 美动医疗实习需求

"这个项目起源于我的实习。一场培训结束的时候， 领导说能不能做个实时的反馈问卷。Poll Everywhere 是很好的工具， 但很多想实现的功能并不能通过现成网站实现。
飞书表格免费，调用飞书 CLI 能操作它，AI 能帮我想题目。 那就把这三件事串起来。"

培训结束，打开飞书妙记，对着它说一句话，评分问卷就自己长出来了。 不是模板——是 AI 读完了你这场培训讲了什么，替你想好了该问什么。 手机打分，大屏 1 秒刷新，数据存自己的飞书 Base。总成本 ¥0。

§ What's Next · 接下来

2026 下半年
要做的

网站读到这里，自然会问的下一个问题——
"那你下一步想做什么？"
α

开一个视频分享账号，
把过程讲出来

过去 3 个月做的东西大部分留在了 README 和 commit 里。下一步想把"怎么和 AI 协作做 Skill""47 轮实验里学到的东西"用视频讲清楚——不是教程，是过程的复盘。文字适合沉淀，视频适合传染。

β

让现有 Skill 进入持续迭代状态

v9.0 是阶段性收敛，不是终点。日常阅读 / 看视频 / 学习里冒出来的新想法和见解，都应该有路径反哺到 Skill 里——让工具跟着我的认知一起长，而不是停在某一版冻起来。

γ

做立足真实业务的 Skill

lark-survey-scoreboard 是个起点——它从美动 HR 实习的真实痛点长出来，而不是为了"做个 Skill 而做"。下一步继续找真实问题、真实需求、有真实用户的场景，用过往项目经验直接落地，不为技术炫技。

δ

突破 AI 的输入端壁垒

AI 现在的产出端工具已经非常成熟（写代码 / 写文章 / 做研究）。但输入端还是壁垒：AI 天然亲近 Markdown，对 PDF / 复杂图文 / 跨领域文献的理解远没到位。我做的 /mineru-pdf 解决了一部分（MinerU API 比 OCR 截图更结构化），但只是把 PDF 转成 MD，不等于让 AI"读懂"。

更大的问题：AI 预训练再大，也会遇到世界知识不够的情况——某个小众领域、某个新兴学科、某份内部文档，预训练里都没有。怎么通过工具 / 主动建知识库 / 辅助搜索，让 AI 能真正读懂跨领域内容？这是我接下来想做的事，方法还在摸索。

灵感来源 · 张小珺对话 Axiom 洪乐潼 — 数学形式化里"知识库 + 搜索 + PDF 转化"的难点，启发了我对通用领域输入端的思考。

§ 三件我比较在意的事
相比"我能做什么"，更想说我在意和正在尝试什么
①

把每一个机制都放到实验里验证

和 Claude Code 协作做了 47 轮控制实验 + 16 轮消融测试。Lost in Middle 关键约束放中间合规率 0% / 放首尾 100%、机制有效 ≠ 必要——这些结论都来自实验本身，不是凭感觉。这是我目前最在意的部分，也是我想继续做研究类工作的原因。

②

把方法论工程化为元工具的尝试

做 Multi-Agent 时发现每轮迭代都在用同一套循环——「读经验 → 诊断瓶颈 → 选变量 → 实验 → 评估 → 沉淀」。把这套循环工程化成 auto-new，回过头驱动 Multi-Agent 自己的 31 轮迭代。把"提炼方法论"本身工程化是我现在的一个长期方向。

③

从真实业务需求长出工具

美动 HR 实习识别培训反馈痛点 → 三周开发 → lark-survey-scoreboard → 入选飞书十佳 → larksuite 官方开源库。一个从真实需求长出来的工具——我尝试理解产品的过程。自己做的产品和大厂一线 PM 做的事不一样，这是我承认的。

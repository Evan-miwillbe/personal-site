ROLE & BUILD RECORD

这个项目，
是怎么被做出来的

最初只是想做一次多 Agent 的尝试。后来它逐渐解决了三个更具体的问题：信息怎么搜、怎么汇总、怎么呈现。写论文、做调研汇报、做 PPT，以及后续不少项目，实际上都接在这条信息处理链路上。

我的角色：提出方向、提供资料、做阶段判断，并把真实使用中暴露的问题带回下一轮。Claude Code 承担了大量代码实现和框架演进；这里不把它写成我独自完成的工程。

起点 · v1先把一次分享里的方法搭成骨架

第一版来自一次老师的语音分享。文件通信、角色专业化和阶段流程成为起点；最初的 PM 中心制、7 个 Agent 和 5 个 Phase，并没有被当作最终答案。

校正 · 论文与失败记录让外部资料和真实问题纠正直觉

随后补读 12 篇论文，并把每次研究暴露的流程问题写入 learning-history。PM 中间层、500 字 handoff 等设计，都在失败或对照实验后被移除或改写。

方法 · 单变量实验与 Git一次只改一个变量，再决定保留还是回退

框架稳定后，用固定课题和真实生产任务测试角色、交接、质检与综合机制。结果有效才 KEEP；证据不足就降级结论；每一轮由 Git 留下可回看的版本。

我的判断 · 两个实际节点决定什么时候值得做，也决定什么时候该停

全量交叉带来新洞察但成本增加 65% 时，我把问题从“要不要做”改为“什么情况下值得做”；连续两轮只是在验证、没有再改框架时，停止继续堆机制。

§ 这五个项目为什么放在一起

它们不是一条事后拼出来、只会上升的成绩线。Multi-Agent Research 先把信息搜集、汇总和呈现做成了一套工作流；后面的项目再把这套底层能力带进元层迭代、个人 Context、团队知识和业务现场。并不是每个项目都直接由它产生，但它为其中很多项目打了基础。

把一件事搜清楚、汇总清楚、呈现清楚，再决定它能不能成为一个真正有用的工具。

从写论文、调研汇报、PPT，到个人知识、团队知识和业务工具；
问题不同，底层仍是怎样搜集信息、汇总信息，再把它呈现清楚。

§ 观点 · Notes

从原理层面
锐评

简历里写了「能从原理层面锐评主流大模型与 Agent 产品的瓶颈」——这里是兑现。
强观点、弱持有（Strong opinions, weakly held），而且都是此刻的判断：这行变得太快，我点到的瓶颈各家都在补，半年后大概率有几条要划掉重写。
Multi-Agent Research 做到 v9.4，最想说的一句 多 Agent 的价值不在「并行」，在「综合层」；框架真正对抗的，是「AI 自欺太容易」——
而逼近真相，从来是一个「下降」的过程，不是「过滤」的过程。
01 · Lost in Middle

关键约束的位置，比措辞更重要

同一条硬约束放 prompt 中段，合规率 0%；移到首尾，100%。换措辞没用，换位置才有用。
这是我那套 harness、那个长度区间测出来的，换模型临界点会变——当先验，不当定律。
02 · 综合层 > 并行

多 Agent 的价值在综合层，不在并行

斯坦福 DPI 定理证明：等算力下单 agent 并不输多 agent。多 agent 真正不可替代的，是把零碎产出熔合出跨板块的新洞察——效率只是副产品。
这对「要综合判断」的任务成立；天然可切分的批量活，并行本身就是收益。
03 · 独立性逐层递进

不让任何角色，既当运动员又当裁判

专家自验证 → QR 独立审查并修复 → Evaluator 只评不改的终裁，每一层都比上一层更「局外」，专治 AI 的「自评偏差」。
既评又改的人会对结果有「所有权」，所以终裁必须只评不改、对历史规范盲。
04 · 像管理一家公司

带 AI 团队，撞见组织设计的难

给子 agent 分工、让一个角色质疑另一个——和带真人团队是同一件事。对照 Block／红杉「裁掉中层」的赌注，我走的是「多角色独立质疑」的另一条路。
AI 让「自己造」变得可能，可什么都自己造未必合理——有些事本来就该放心交出去。
读完整的六节反思 从 prompt、架构、质检、输入端，一路谈到组织与个人——每条都带我自己的实验和边界

lark-survey-scoreboard 是个起点——它从美动 HR 实习的真实痛点长出来，而不是为了"做个 Skill 而做"。下一步继续找真实问题、真实需求、有真实用户的场景，用过往项目经验直接落地，不为技术炫技。

δ

突破 AI 的输入端壁垒

AI 现在的产出端工具已经非常成熟（写代码 / 写文章 / 做研究）。但输入端还是壁垒：AI 天然亲近 Markdown，对 PDF / 复杂图文 / 跨领域文献的理解远没到位。我做的 /mineru-pdf 解决了一部分（MinerU API 比 OCR 截图更结构化），但只是把 PDF 转成 MD，不等于让 AI"读懂"。

更大的问题：AI 预训练再大，也会遇到世界知识不够的情况——某个小众领域、某个新兴学科、某份内部文档，预训练里都没有。怎么通过工具 / 主动建知识库 / 辅助搜索，让 AI 能真正读懂跨领域内容？这是我接下来想做的事，方法还在摸索。

灵感来源 · 张小珺对话 Axiom 洪乐潼 — 数学形式化里"知识库 + 搜索 + PDF 转化"的难点，启发了我对通用领域输入端的思考。
